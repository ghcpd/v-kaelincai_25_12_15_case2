## 3.4 New System Design (Greenfield Replacement)

**Target State:** Robust appointment booking system with state management, avoiding assignment errors like ranking ties.

**Service Decomposition:** Single Flask service with DB.

**Unified State Machine:**
- init → booked (success)
- init → failed (conflict/invalid)
- booked → cancelled (if needed)

**Idempotency/Retry/Timeout/Circuit-Breaker Strategies:**
- Idempotency: Check key before processing.
- Retry: Client-side with backoff.
- Timeout: 30s default.
- Circuit-Breaker: N/A (no external deps).

**Compensation (Saga/Outbox):** Saga for multi-step (e.g., if payment added), but simple here. Outbox for events if needed.

**Architecture & Data Flow (ASCII):**
```
Client → POST /appointments → Validation → Idempotency Check → Conflict Check → DB Insert → Response
                                      ↓
                                   Failed → Response
```

**Key Interfaces/Schemas:**
- API: POST /appointments
  - Request: {"idempotency_key": "string", "user_id": "string", "datetime": "ISO8601"} (constraints: key unique, datetime valid future)
  - Response: {"appointment_id": "uuid", "status": "booked|failed", "datetime": "ISO8601"}

**Migration & Parallel Run:**
- No direct migration (domain change).
- Parallel: Run legacy ranking, new booking separately.
- Cutover: Feature flag, full switch after validation.
- Rollback: Revert to legacy if issues.
