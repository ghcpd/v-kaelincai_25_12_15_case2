# 🛠️ 3.4 Greenfield Design (v2 replacement)
I created fast-oswe-1206 with a minimal v2 design. The design principles applied:

- **Stateless functional service** — pure function `RankingService.calculate_rankings`.
- **Deterministic ordering** — sort by score desc + name asc (for tie determinism).
- **Idempotent behavior** — same input yields same ordering; `idempotency_key` for observability.
- **Structured logging** — JSON-friendly messages (rich `extra` fields).
- **Validation & contracts** — input validation and typed dataclasses.

---

## 🔁 Target architecture (high-level)

```
+---------------------------------------+
|  Client/API -> HTTP/REST -> service ------------------+
|                                                        |
|  +------------+    +-------------+    +------------+   |
|  |  API Layer | -> | Ranking API | -> | Ranking DS |   |
|  +------------+    +-------------+    +------------+   |
|                                                        |
|  (Sagas / Outbox pattern for notifying downstream)    |
+--------------------------------------------------------+
```

**Key pieces (recommended for greenfield):**

- **Service**: `RankingService` (stateless; pure function), packaged as a small microservice or function (e.g., AWS Lambda / serverless).  
- **API**: REST/HTTP endpoint `/rankings` that accepts a list of student objects, returns ranked list.  
- **Idempotency / Retry**:
  - Use idempotency key on the request so duplicate requests are safe to retry.
  - For external operations (e.g., notifications) use **transactional outbox** or **saga** pattern.
- **Circuit Breaker / Timeout**:
  - Implement per-call timeout (e.g., 100 ms) in API Gateway or client wrapper.
  - Circuit breaker upstream if dependencies amplify (e.g., downstream storage).
- **Compensation**: If ranking triggers side-effects (publish results, award allocations), use **saga** with compensation steps (undo if needed).
- **Observability**:
  - Structured logs include `request_id`, `idempotency_key`, `student_count`, `result` snapshots.
  - Metrics: `ranking_requests`, `ranking_failures`, `ranking_latency_p50/p95`.
- **Validation & constraints**:
  - Score in 0..100 numeric, `name` non-empty string, max length (suggest 50 chars), maybe dedupe names.
